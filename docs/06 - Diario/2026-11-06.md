## Decisiones

| Tema | Decisión |
| --- | --- |
| Versión de Spring Boot | `4.1.2` (sin sufijo `.RELEASE`, que Initializr devuelve en el identificador pero Maven Central no publica con ese nombre). |
| Starters de Boot 4 | `spring-boot-starter-webmvc` en lugar de `spring-boot-starter-web`; los starters de test también están separados. Flyway necesita `spring-boot-starter-flyway` para que se registre la auto-configuración. |
| Seed | `V2__datos_iniciales.sql` vive en `db/dev` y solo se carga con los perfiles `dev` y `test`; producción no recibe cuentas de ejemplo. |
| Migraciones | El servicio Flyway de Compose aplica el esquema y el backend vuelve a validarlo al arrancar; es idempotente. |
| Perfiles | `dev` por defecto; `test` en las pruebas. `application-test.yml` se duplica en `src/test/resources` para que los tests no dependan del classpath de producción. |
| Health | Se expone solo `health`, sin detalles, para no filtrar información interna. |

## Problemas

- El ZIP de Initializr generó `<version>4.1.2.RELEASE</version>`, que Maven no resuelve. Se corrigió a `4.1.2`.
- El JDK por defecto de la máquina es 27; para Maven se usa `JAVA_HOME=/home/alvarogm/.jdks/ms-21.0.12.1`.
